## The supervised run, which is the actual test

The fort is paused at tick **272606** and paused is the safe state. You are
authorised to unpause it (the user has granted full authority; this is a dev
experiment and the fort is expendable), under these rules:

1. **Quicksave first and confirm it wrote** by polling the save slot mtime
   (`docs/TRAPS.md`: quicksave is asynchronous; poll up to about 90s).
2. **Supervised, with a remote watchdog that re-pauses**, using **absolute
   paths**. Know the watchdog's weakness: on 2026-09-19 an unbounded query
   wedged the DFHack command pipe and **took the watchdog's pause call with
   it**. So:
3. **Never run an unbounded query against the live process.** Bounded,
   targeted reads only. The sampler itself must also be bounded: specific
   vectors, never map tiles.
4. **Run for about 8 game days (around 9,600 ticks)**, long enough to see
   **several samples accrue and one `overseer-autosave` fire**. That second
   observation matters on its own: the autosave was registered this morning
   and **has never been seen firing**, because the fort has been paused ever
   since. Confirm it by a save-slot mtime change during the run.
5. Re-pause and verify the pause and tick by bounded reads.

- **Every line parses** as the contract's format, and `metrics` covers the

- **A failed read shows as `null` plus `error`, never `0`.** Prove it the way

- **The game's pace was not visibly hurt.** Record wall-clock seconds per game

`mint` and `sample`. Design choices worth recording:

- `is_fort_owned`/`is_on_hidden_tile` are **copied verbatim**, not
  `reqscript`'d, from `df-overseer-stocks.lua` -- that file's predicate is a
  local function, not exported, and this stream's own touched surfaces
  exclude editing that file. The logic is unchanged, the binding is
  necessarily duplicated.
- A **hand-rolled JSON encoder**, not the bundled `json` module every other
  `df-overseer-*.lua` file uses. The contract requires a literal `null` for
  a failed read's `value`, and in Lua a table field set to `nil` is simply
  **absent**, not present-as-null -- `df-overseer-stuckjobs.lua`'s own
  `idle_ticks = idle_ticks` idiom (cited approvingly in
  `df-overseer-stocks.lua`'s header) relies on exactly that omission, and
  the 2026-09-19 deploy-and-live-verify write-up independently confirms it:
  a broken lookup there made the field "absent from the object entirely --
  not present, not 0". That is fine for that tool's own contract (caller
  checks key presence) but is not what `docs/TIMESERIES.md` asks for, so
  rather than assume the bundled encoder's null-handling one way or the
  other, this file encodes its own fixed record shape by hand.
- Timeline state (`timeline_id`, `timeline_start_abs_tick`) lives in a
  two-line text file, `dfhack-config/timeseries/.current_timeline.txt`, not
  a Lua global -- `reqscript`'s module cache persists for the life of the
  DFHack **process**, which can outlive one map load, so a Lua global would
  not reliably reset "once per map load" the way the contract requires.
  `mint` (called once, from `onMapLoad.init`) writes it fresh; `sample`
  (called by the `repeat`) reads it, and self-heals with a loud warning if
  it ever finds no state (a `sample` firing before any `mint` this load).
