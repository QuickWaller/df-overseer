# Handoff: audit pre-existing repo-vs-VM drift on VM 103 and VM 106

Date: 2026-09-28. **Researcher, Sonnet. Read-only against both VMs. No file changes on either VM, no deploy.**

## Context

While deploying tool fixes on 2026-09-25 (`evals/live/2026-09-25-first-real-conductor-cycle/README.md`,
"Pre-existing deploy drift found and deliberately not touched"), a hash comparison
found these files on VM 103's `/opt/df/dfmcp-smoke/` tree differ from the repo,
for reasons predating that day's work and never explained:
`ROSTER.yaml`, `agents/conductor/role.md`, `agents/consultant/role.md`,
`agents/consultant/sites.yaml`, `agents/quartermaster/role.md`, `dfmcp/README.md`,
and five Lua scripts in `/opt/df/game/hack/scripts/`: `df-overseer-chokepoints.lua`,
`df-overseer-diggable.lua`, `df-overseer-openarea.lua`, `df-overseer-stockpile.lua`,
`df-overseer-ui.lua`. None of these were touched by the 2026-09-25 streams.

## Task

For each differing file, read both the committed version (`git -c core.autocrlf=false
show HEAD:<path>`) and the live VM copy, and answer: **what is the actual difference**
(a real content diff, not just a hash mismatch), and **is the VM ahead of the repo
(an undeployed fix or hand-edit) or behind it (a repo change never deployed)?**
Cross-reference `decisions/DECISIONS.md` and `handoffs/INDEX.md` for whichever
stream last touched each file, to explain *why* it drifted, not just that it did.

Use `scripts/vm-ssh.sh df '...'` for VM 103 and `scripts/vm-ssh.sh openclaw '...'`
for VM 106 (both already exist in this repo). Read files with `cat`/`sha256sum`
over SSH; do not modify anything on either VM. This repo's own trap applies:
`dfhack-run` output carries ANSI escapes needing stripping, but you are only
reading plain files here, not calling dfhack-run for this task.

## Produce

A short report (`docs/DRIFT-AUDIT-2026-09-28.md` or inline in your Result section,
your call on which is more useful) listing, per file: repo path, VM path, whether
VM is ahead/behind/functionally-equivalent-but-reformatted, the actual diff
(trimmed if long), and a one-line recommendation (redeploy from repo / update repo
from VM's live fix / leave alone and say why).

## Rules

- `git merge --ff-only main` first; this brief is committed on main.
- Read-only on both VMs: no writes, no restarts, no deploys.
- Do NOT touch `Working.md`, `decisions/DECISIONS.md`, `memory/`, `handoffs/INDEX.md`
  beyond this brief's own Result section.
- No em dashes in prose.
- Commit your report file (if any) when done. Do not push. Stop and report on any
  permission refusal.
- Fill in the Result section with your top-line findings (which files are ahead,
  behind, or equivalent) in under 200 words, pointing to the full report for detail.

## Result

Full detail: `docs/DRIFT-AUDIT-2026-09-28.md`.

**Six doc/role files (ROSTER.yaml, conductor/consultant/quartermaster
role.md, consultant/sites.yaml, dfmcp/README.md): VM behind repo.** All six
share one live mtime, 2026-09-22 01:43:45 UTC, the loop-MVP deploy; none
were touched by any deploy since, while the repo kept editing them through
2026-09-25. Most consequential: the live consultant's own charter still
describes the pre-wiki-mirror tool surface (no `wiki_search`, no
staleness/HELD language), even though the mirror switch-over is reported
live elsewhere. ROSTER.yaml's actual data (enabled flags) already matches
the repo; only its header narrative is stale. Cause looks like an omission
in what each post-2026-09-22 deploy's file list covered (these files aren't
read by `dfmcp-server` itself), not a deliberate decision.

**Five Lua scripts (chokepoints, diggable, openarea, stockpile, ui):
functionally equivalent.** The raw diff looked large but was entirely an
artifact of `vm-ssh.sh`'s address-scrubbing, which also masks
`df-overseer-*` script names inside file content. Normalising that out,
every file differs from the repo by exactly one trailing blank line at EOF
(confirmed with `xxd`), no logic or comment content differs. Leave alone.
