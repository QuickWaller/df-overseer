**Signatures and output fields for 2C's TOOLS.yaml**

- `blueprint.status SITE_ID [PHASE]` (read). Existing fields unchanged; new
  top-level `phase` (null without PHASE, an error string `no phase ...` for an
  unknown or notes/aliases/ignore label):
  `phase: {label, mode, applied, leaves: [leaf labels], cells: {carve_required,
  carve_dug, carve_solid, smooth_required, smooth_done, rough, undesignated,
  hidden, unreadable}, buildings: [{kind, complete: true|false|null}],
  zone_required, zone_present: true|false|null, unread_modes: [], done}`.
  `done` = applied (every leaf of the phase appears in the site's applied
  phases) AND dig leaves done (no solid carve cell, no rough smooth cell, none
  hidden or unreadable) AND every building at `getBuildStage() >= getMaxBuildStage()`
  AND, if the phase has a zone leaf, a civzone on every zone cell AND no
  unread mode. Any null read holds done false. A building seen on several
  cells is one entry (dedupe by building id). `place` (stockpile) leaves count
  complete when a building exists. Suggested `progress` mapping:
  `{tool: blueprint.status, args: {site_id: "$handle", phase: "$phase"}, done_field: phase.done}`
  (the design's `args` names match). Stall and unsmoothable signals are
  unchanged elsewhere in the output: `dig.state`, `finish_state.blocked_total`.
- `level` (relative to the landmark, integer; null only for a site stored
  before this change): `reserve` output top-level `level`; `apply`/`preview`
  output `site.level`; stored on the reservation and the site record.
  `resolution_fields` for a reserve can use top-level `level`.
- `blueprint.sites` rows gain `reservation` (the `res-N` it was carved from, or null).
- `blueprint.reserve` dry run, real run and overlap refusal all carry
  `finish_plan` (same shape as apply's: required_cells, smoothable,
  already_finished, blocked_by_material, blocked_total, occupied_by_building,
  hidden, other_shape, unreadable), over every #dig section of the template.
- `blueprint.release SITE_ID [DRY_RUN] [ANY_PENDING]`. Default unchanged
  (dig-only phases, stalled sites only). With `ANY_PENDING=true`: skips the
  stalled requirement, undoes the site's dig phases via quickfort `undo`,
  never touches dug tiles; output gains `any_pending`, `skipped_phases`
  (non-dig phases applied to the site, named and NOT withdrawn) and a
  `cannot_undo` note. On success the site record is forgotten
  (`site_forgotten`).

**Design problems found**

1. **Bug in current deployed code, fixed here:** a later phase on a `site-N`
   that was carved from a `res-N` was refused by its own reservation
   (`blocked`, "this tool is not that reservation's holder"), because only
   the first apply (SITE=`res-N`) passed the holder. The fixtures exposed it.
   Every multi-phase reserved room would have blocked at phase 2. Fix: holder
   = `from_reservation or site.reservation`. Test added. The live fort's
   bedroom/office rooms were not reserved through this path before, so it was
   never hit.
2. `release ... ANY_PENDING` cannot withdraw planned buildings or zones (the
   quickfort `undo` of build/zone modes is unverified here); it reports them
   as `skipped_phases`. Design 4.4 says "withdraws that site's outstanding
   designations": true for dig and smooth only. 2C/2D should treat a planned
   but unbuilt bed or zone as left behind (harmless but present) and say so in
   the `close` record.
3. `release` forgets the site on success, so the cleanup's second attempt for
   the same handle gets a `no site` error, not a no-op: D must treat that
   error on a `cleanup:<handle>` run as already released.
4. Resolution check: `near_landmark` is also in `finish_plan`-bearing
   outputs only via reserve; nothing else needed.
5. Fixtures are from the Lua source with a stubbed world (stub kind tables
   give bed/chair/bedroom/office); the real values are pending the
   supervised bedroom, as design 2.3 says.
