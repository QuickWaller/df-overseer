## Decided (do not re-open)

- Authority option C: the plan stands on the Planner's say-so; the Overseer
  rules only action proposals.
- Q1 option b: the server **accepts and flags** plan mistakes (kind typos,
  unknown landmarks, oversized sections, malformed signals); it never
  refuses them for content. Flags come back in `plan.write`'s reply and are
  inert until fixed. A version that only fixes flagged entries is exempt
  from the season interval. (Refuse only what cannot be stored at all:
  wrong writer role, coordinates, a payload that is not the schema shape.)
- Q2: seasonal versions are free; a mid-season version must cite an
  accepted `plan_change` ruling; the server rate-limits `plan_change`
  requests (cooldown and per-season cap, policy data). Fix-only versions
  need no ruling.
- Q3: the shortfall watch ships switched off (P1b), so v1 can be read first.
- Q5: the Architect's routine wake retires in P1b.

### Design ambiguities resolved (simpler reading taken)

1. **Flags are stored on the record** (`flags`, plus `cited` on `relies_on`), so
   the fix-only exemption is computable from the active version alone. Info
   flags (`kinds_unchecked`, `unreadable_citation`) are not inert.
2. **Fix-only** = every change is a `changed` or `removed` of an entry the active
   version flagged inert; an added or reordered entry, or any unflagged change,
   is not exempt. A version with no changes is refused ("nothing changes").
3. **Over-cap entries** are kept and flagged `over_cap` (inert), never dropped.
4. **Sections beyond targets** (districts, closeness, industries, flows, access)
   have no home yet: `plan.write` refuses them by name with their stage. The
   policy lists the caps for later.
5. **Guardrail 2 (built rooms) is vacuous in P1**, as the design says; there is
   no binding code, only a test that a target-only plan needs no ruling.
6. **`in_flight` counts each serving root proposal as one template unit** from
   pending, through accepted, to an open project; a finished project drops out.
   The design's per-site "counted until its own zone is on hand" rule needs the
   P2 `site_handle -> zone` binding and is not built; `target_position` takes
   the number the caller computed, so P2 swaps the producer only.
7. **`furnished` and `.furniture."F"` signals read UNRESOLVABLE until `zone.list`
   carries `furnished_by_kind` and `furniture_counts_by_kind`.** The Lua read is
   not built (the handoff touches no Lua). A target on these shows `unresolved`,
   never a shortfall. **P1b or a small Lua stream must add those two fields to
   `zone.list`'s summary before `plan_watch` can be switched on**; `.count` works now.
8. **`plan.read` before version 1** returns the default plan with a note, not an error.
9. **The Planner `queue.pass` records the review tick in the `meta` table**
   (no schema bump); `last_reviewed_tick` is the later of that and the active
   version's tick.
10. **Derived-input availability** reads `stocks.availability` with TYPE from
    `plan_policy.yaml` `item_types` (bed to `BED`); the owner from `item_owner`.
    It reports a short input line only for targets with serving work.
11. **Token and openclaw plumbing**: only the `.env` placeholder is added. The
    pinned openclaw config, `conductor/config.py`, `triage.py` and
    `infra/conductor.example.env` are P1b (conductor is off limits here).
