# Free Third-Party Graphics Packs for DF Classic 0.53.16 (v50-era engine)

Date: 2026-09-09
Scope: Dwarf Fortress Classic 0.53.16 (the exact ITCH build `scripts/install_df.py` installs), DFHack 53.16-r1.1. Purely cosmetic, for human VNC/screenshot viewing — no bearing on `docs/PURPOSE.md` design commitment #1 (the agent never perceives a rendered map).
Status: research only. Nothing installed, no VM touched. This is the explicitly-scoped-secondary fallback that `research/2026-09-09-df-modern-graphics.md` named but did not design: since that spec established there is no free path to Kitfox's own proprietary Premium tileset, this spec surveys the free third-party alternative instead.

## Bottom line

**The genuinely-v50-compatible options are much scarcer than DF's tileset reputation suggests.** Every one of the historically famous, oft-recommended pre-v50 packs checked in this pass (Phoebus, Ironhand, Mayday, Spacefox, CLA, Obsidian, Meph, Taffer, GemSet, Curses of Balin) tops out at DF 0.47.x or earlier, with no v50/0.53.x port found anywhere — including packs whose *maintainers were still actively shipping releases in 2025* (Taffer's most recent release, dated April 2025, still targets "0.42.05 - 0.47.04," not v50). Community graphics content simply has not caught up to the v50 engine transition the way this project's own `memory/dfhack-environment.md` already found true of DFHack tools — the same caution the task asked to apply here turns out to bite harder than expected.

Only **one** pack surfaced in this research with an explicit, primary-source statement of v50/Premium-era compatibility and its own confirmation of working on free Classic: **HEWN**. Two more well-regarded packs (**Vettlingr**, **Bitlands**) are real, free, actively-hosted, and stylistically relevant, but their v50 compatibility could not be confirmed and in Vettlingr's case is contradicted by the primary distribution file — flagged explicitly below rather than glossed over.

## Shortlist

### 1. HEWN — the only pack with verified v50/0.53.x compatibility

- **Style**: A "traditional roguelike" retro pixel-art overhaul, explicitly inspired by Caves of Qud and by Bitlands (below) — not a photorealistic or painterly style, more a clean, saturated, single-tile-per-creature icon style. Creatures are "1-tile-large, differentiated by color and silhouette" rather than large detailed sprites; stones/ores get functional color-coding (white = not fire/magma-safe, grey = fire-safe, dark grey = magma-safe; copper/iron/tin/silver each individually colored). Coverage is total: all Fortress Mode UI, creatures (including separate sprites for children, babies, corpses, ghosts, undead), professions (miners, soldiers by weapon type, nobles, scholars), plants, buildings, liquids and particle effects. Adventure Mode is explicitly unsupported. This is closer to "stylized modern roguelike" than to Steam Premium's actual pixel-art sprite look — it is the pack in this list *least* likely to be mistaken for Steam's own art, but the *most* likely to actually render correctly on this project's exact build.
- **v50/0.53.x compatibility — confirmed, high confidence**: the DFFD listing states outright: *"This modification is designed for DF Premium v53.10. Support for other versions is not guaranteed. This does seem to work for Classic!"* (verified: primary distribution page, `dffd.bay12games.com/file.php?id=17744`). A second, independent DFFD upload (`file.php?id=17759`, "DF classic 53.10 + DFHack 53.10-r1 + HEWN") bundles DF Classic 53.10, DFHack 53.10-r1 and a pre-applied HEWN install together as a single "unzip and play" archive with 15,000+ downloads — strong corroborating evidence this pack is genuinely used on free Classic by a real community, not just claimed compatible in passing. *Caveat*: the stated target is 53.10; this project's pin is 53.16, six patch releases later. Since graphics packs are pure raw-folder data (confirmed mechanism from `research/2026-09-09-df-modern-graphics.md` Q2 — `[TILE_PAGE]`/`[CREATURE_GRAPHICS]` tags, no compiled-code dependency), a six-patch gap is unlikely to break it, but this was not tested live and should not be treated as certain.
- **License/source**: **CC BY-NC-SA 4.0** (verified from the Steam Workshop listing) — non-commercial, share-alike, attribution required. Available three ways: DFFD (`dffd.bay12games.com/file.php?id=17744`, direct zip, no Steam account needed), Bay 12 Forums (`bay12forums.com/smf/index.php?topic=183729.0`, inaccessible to this research pass — blocked by the forum's anti-bot page, so not independently re-verified there), and Steam Workshop (`steamcommunity.com/sharedfiles/filedetails/?id=3662002056` — not usable by this project since Classic has no Steam Workshop integration; listed only as evidence of the same asset being distributed multiple ways).
- **Install mechanics vs. this project's blocker**: this is the one candidate that directly and provably answers the exact `USE_CLASSIC_ASCII:NO` blank-map problem this project already hit (`decisions/DECISIONS.md` 2026-09-09; `research/2026-09-09-df-modern-graphics.md` Q2) — it ships real `raw/graphics` tile-page data, which is the one thing free Classic's archive lacks by design. Per its own description, installation is not the old "drop files into raw/graphics, install an LNP" convention most legacy packs use — it installs as a selectable **mod module** through v50's newer pre-worldgen mod-selection screen (the description talks about deactivating vanilla asset modules — Materials, Environment, Plants, Buildings Graphics, Creatures Graphics, World Map, Interface — and enabling HEWN's replacements instead), plus a manually-copied `colors.txt`/`black_background.bmp` pair described as "strongly recommended." Mechanically this is still the same `[TILE_PAGE]`/raw-graphics mechanism underneath (v50 didn't change that system, just added a UI for module selection at world-gen time — consistent with the mechanism already verified in the prior research pass), but the *install procedure* differs from older packs' plain folder-drop. `USE_CLASSIC_ASCII:NO` must still be set (their instructions say "disable Use Classic ASCII Glyphs") — same setting this project's `scripts/install_df.py` already knows how to write via `step_init`, just left at YES today specifically because nothing supplied real graphics data. A world built with this mod selected would need regenerating (mods apply at world creation, not to an existing save) — relevant since this project's `Working.md` records no world has been generated yet, so this is not a disruptive re-gen for an existing fort.
- **Why it made the list**: it is the only candidate in this entire survey with a primary-source, dated (2026), actively-corroborated statement of working on this project's exact engine generation and even a pre-bundled installer targeting almost this exact DF/DFHack version pair.

### 2. Vettlingr — closest to the "modern, Steam-style" look the user actually asked for, but compatibility is a real open question

- **Style**: 32×32 sprite tileset, full creature/environment coverage, described (including by its own author's community reputation) as a "darkest dungeon inspired style" with "a slight dystopic feel" for murkier fortress interiors — detailed, moodier pixel art, not a flat glyph-swap. This is visually the closest match in this survey to what "modern, detailed sprite tileset" usually means, closer in spirit to Steam Premium's commissioned art than HEWN's icon-style approach.
- **v50/0.53.x compatibility — unverified, and the sources actively disagree.** The only version-labeled primary distribution file found (`dffd.bay12games.com/file.php?id=14072`, "Vettlingr barebones — Outlined Edition") states its target DF version as **0.47.05**, last updated December 2022 — pre-v50. A third-party listicle (gamerant.com) separately claims Vettlingr is "compatible with current versions" and superior to Steam's own graphics — this is the kind of docs-vs-primary-source disagreement this report is obliged to flag rather than silently resolve: **the primary distribution file is trusted over the listicle claim**, so treat Vettlingr as *not confirmed* for v50 until tested. One additional, unconfirmed signal: a Patreon post titled "Vettlingr Module" (`patreon.com/vettlingr/posts/vettlingr-module-74530988`) suggests the artist may be doing v50-module-system work in progress, but the page returned HTTP 403 to this research pass and could not be read — its existence is noted, its content is not verified, and whether any resulting release is free is unknown.
- **License/source**: "Use of sprites outside of DF is prohibited unless you have special permission" (verified from the GitHub repo README) — free to use in-game, not CC-licensed, no redistribution beyond the game itself. Source: `github.com/DFgraphics/Vettlingr` (a "lite" fork; the full pack is only on the Bay 12 Forums thread `topic=172078.0`, which this research pass could not fetch — blocked by the forum's Anubis anti-bot page).
- **Install mechanics**: the DFFD file uses the older LNP-era convention (a folder dropped into `LNP/graphics/`), which presupposes the Lazy Newb Pack tooling this project does not use and which itself predates v50. Would need real live testing to know whether the 0.47.05-targeted raw files even load without errors against 0.53.16's raw-format expectations — not something inferable from documentation alone.
- **Why it made the list**: named explicitly because it is the pack most likely to be what the user pictures when they say "modern, Steam-style" — but the compatibility gap is real and stated plainly rather than glossed over, per this task's own instruction to flag confidence per candidate.

### 3. Bitlands — minimalist/clean, ASCII-aesthetic-preserving, actively hosted, compatibility also unconfirmed

- **Style**: Explicitly *not* a departure from DF's ASCII look — it "completely overhauls the graphics while preserving the ASCII aesthetics," redrawing all ~50,000+ underlying textures in a cleaner, more legible version of the classic glyph grid rather than replacing glyphs with sprite art. This is the one candidate that is honestly closer to a very thorough font/glyph replacement than to a Steam-style sprite tileset — flagged clearly per the task's CLA-vs-sprite distinction, since a user picturing "modern Steam look" would likely find this too close to vanilla ASCII to satisfy that ask, even though it is technically a full graphics-set replacement, not a plain font swap.
- **v50/0.53.x compatibility — unverified, and one secondary claim found is likely mistaken.** No explicit DF-version statement was found in the GitHub README or its single tagged release (`1.0.0`, dated November of an unstated year — the release notes did not load fully for this pass). The repo's own build pipeline (`raw/objects` folder copied into a `scripts/` directory, Python generation scripts, then "DFPatch" to apply the result) is the older, pre-v50-era raw-patching workflow, which is circumstantial evidence against a v50 port having happened, not proof either way. One secondary source's claim that Bitlands is "now included with modern downloads of the title" was checked against this project's own prior primary-source research (`research/2026-09-09-df-modern-graphics.md`, Q1) and appears to be **incorrect or confused**: that prior research verified directly from Kitfox's own storefront and devlog that Premium's bundled tileset is proprietary commissioned art by Carolyn Jong and Neoriceisgood, with no mention anywhere of Bitlands. Treated here as a clear case of a secondary source being wrong, not as evidence of Bitlands compatibility.
- **License/source**: **CC-BY-4.0** (verified, GitHub README) — the most permissively licensed candidate in this survey. Source: `github.com/DragonDePlatino/bitlands`.
- **Install mechanics**: uses the same DFPatch-based pipeline noted above; the README's own guidance is to use a pre-built release archive rather than building from source, but the release's version target is unconfirmed.
- **Why it made the list**: it's the cleanest, most permissively-licensed, most actively-hosted "minimalist" option found — worth naming for that reason even though its v50 status is genuinely unresolved, and even though on inspection it may not deliver the "modern sprite" look the user is after regardless of compatibility.

## Installation mechanics: general comparison across candidates

All candidates in this survey use the same underlying, verified DF mechanism (`research/2026-09-09-df-modern-graphics.md` Q2): a `raw/graphics/graphics_<name>.txt` file with `[OBJECT:GRAPHICS]`/`[TILE_PAGE]`/`[CREATURE_GRAPHICS]` tags, plus `USE_CLASSIC_ASCII:NO` in `prefs/init.txt` to actually switch the renderer to read it — the identical setting this project's `scripts/install_df.py` `step_init` already knows how to apply and currently leaves at YES for exactly the reason this research exists. None of these packs touch the `dwarfort`/`dfhack` executables or DFHack's compiled memory offsets — they are pure data, so the compatibility risk this project already flagged around mixing Premium's *binary* (`research/2026-09-09-df-modern-graphics.md` Q3) does not apply here; DFHack 53.16-r1.1 should be unaffected by any of these regardless of which pack is chosen.

Where they differ:
- **HEWN** installs through v50's newer pre-worldgen mod-selection screen (enable/disable raw modules), a UI that did not exist pre-v50 — this is itself indirect corroboration that HEWN's authors built against the current engine rather than an old convention.
- **Vettlingr** and **Bitlands** both assume older tooling (an LNP `graphics/` folder for Vettlingr; a from-source Python+DFPatch pipeline for Bitlands, though pre-built releases exist) that predates v50's mod-selection screen — consistent with, though not proof of, their uncertain v50 status.
- A world must be (re-)generated with a graphics mod selected for HEWN's mod-based install to take effect, since mods apply at world creation. Since `Working.md`/this project's status notes no world has been generated yet, this is a non-issue for a first embark, but would matter for switching packs on an existing fort later.

None of this was tested against a live install in this research pass, per the task's explicit "do not touch any VM" instruction.

## Follow-up, 2026-09-09: Vettlingr deep-dive and style-alike alternatives

Prompted by explicit user feedback after reviewing the shortlist above: the user likes Vettlingr's style the most (32×32 detailed, moody, "Darkest Dungeon"-esque sprite art) and asked for deeper digging on its actual v50 status, plus a search for other packs in the same visual niche (detailed moody sprites, not HEWN's flat-icon style, not Bitlands' ASCII-preserving style) confirmed to work on v50/0.53.x.

### Bottom line: the gap got clearer, not smaller. Vettlingr is now ruled out with much higher confidence, and no same-style alternative was found.

This pass reached primary sources the first pass could not (GitHub's API directly, rather than just the rendered page; the DFHack docs; the DF Wiki's actual current-namespace state) and every one of them adds independent corroboration that Vettlingr has no v50 port, plus a new *technical* reason (not just an absence of a version-labeled release) why its full feature set cannot work on v50 even if someone forced the raw tile data to load.

### Vettlingr: the open questions from the first pass, resolved

- **GitHub repo history, checked via `gh api` directly (not the rendered page) — highest-confidence check possible in this pass.** `repos/DFgraphics/Vettlingr`: created 2020-04-05, **last pushed 2021-03-06**, exactly 7 commits total, the last one titled *"updated for Dwarf Fortress v0.47.05"*. Only two tags exist, `47.05` and `1.4a` — nothing later. Verified, primary source, high confidence: this repo has had zero v50-era activity of any kind, not merely no version-labeled release.
- **The one open GitHub issue is itself evidence, not just silence.** Issue #1, opened 2022-07-21, titled *"update to 1.6-1?"*, body: *"I think last update was on Jul 07, 2022."* This is a community member asking the repo maintainer to catch up to the artist's newer Patreon-only version (1.6.1) — a version that, per the next finding, is **also** pre-v50. So even the discontented issue-filer wasn't asking about v50 support; the whole conversation is scoped to 0.47.x. Verified, primary source.
- **The newest known Vettlingr release is confirmed still pre-v50.** DFFD file id=15736, titled *"DF47.05 Windows Vettlingr1.6.1"* — the same 1.6.1 version referenced in the GitHub issue above, and its own filename brands it "DF47.05." Verified, primary source: the most recent version of Vettlingr that exists anywhere, patron or public, targets 0.47.05.
- **The artist's own current distribution hub is still branded pre-v50.** A Patreon post titled *"DF47 Vettlingr Tileset Download Linktree"* (`patreon.com/posts/df47-vettlingr-76277493`) surfaced via WebSearch — the post itself returned HTTP 403 to WebFetch (same wall as the first pass's Patreon check), so only the title is confirmed, not the body. But the title alone is a meaningful data point: the artist's own current link-hub for their tileset is self-labeled "DF47," not "DF50" or "DF53" or version-agnostic. Medium confidence (title only, unread body).
- **New technical finding: Vettlingr's "Module" edition depends on TWBT, which DFHack itself confirms is dead post-v50.** A second Patreon post, *"Vettlingr tileset Module"* (`patreon.com/vettlingr/posts/vettlingr-module-74530988`, also 403 to WebFetch — same block as the first pass), was described in WebSearch result snippets as *"a modular edition that requires manual install with a copy of DFhack and TWBT."* TWBT ("Text Will Be Text") was the pre-v50 DFHack plugin that let tilesets render multi-tile creatures and custom color/font layering. Checked directly against DFHack's own current documentation (`docs.dfhack.org/en/51.13-r1/docs/about/Removed.html`, fetched and verified, primary source): TWBT is listed under **Removed tools**, with the stated reason "No longer useful post-v50." This is a new, independent, technical reason beyond "no version-labeled release exists": even Vettlingr's most feature-complete edition has a hard dependency on a DFHack plugin that DFHack's own maintainers confirm cannot run on the DFHack version this project uses (53.16-r1.1). This was not identifiable from the first pass's sources and materially raises confidence that Vettlingr cannot deliver its full advertised feature set on v50, independent of whether its raw graphics files would load at all.
- **No independent v50 port exists in GitHub's fork network either.** `gh api repos/DFgraphics/Vettlingr/forks` returns zero forks. A broader `gh api search/repositories?q=vettlingr` search found exactly one other repository anywhere on GitHub referencing the name: `odysseyalive/duerer-vettlingr-twbt`, described as *"Duerer Tapestry for Dwarf Fortress 47.05"*, last pushed 2023-12-18 — eight months **after** v50's general release (v50.06 was already live by Jan 2023, per a dated Steam Community post found in this pass). Fetched directly: its own README states it targets *"Dwarf Fortress 0.47.05"* and *"DFHack 0.47.05-r8"*, with no mention of v50 anywhere. This is a concrete, checked example of exactly the "recently touched but still building for the old engine" pattern this project's `memory/dfhack-environment.md` already documented for DFHack tools generally — now independently confirmed for a Vettlingr-adjacent repo specifically, not just inferred by analogy. Verified, primary source.
- **The DF Wiki's own master graphics-set index has not been migrated to a current-version namespace at all.** The wiki's versioning convention (confirmed via WebSearch and direct fetch) is that v50-era content moves to the main namespace while pre-v50 content stays under a `DF2014:` prefix. The main-namespace page a reader would expect for this, `dwarffortresswiki.org/index.php/Graphics_sets`, was fetched directly and is **a bare redirect to `DF2014:Graphics set repository`** — i.e., the wiki community has not built a current-namespace version of this page at all, three-plus years after v50 shipped. The DF2014 page it redirects to lists every historically-known pack (Vettlingr, Meph, GemSet, Bitlands, CLA, Ironhand, Mayday, Obsidian, Phoebus, Spacefox, Tergel, Taffer, Duerer, Rally Ho!, Geoduck's, Dungeon Set, Anon's) at 0.42–0.47 targets with zero v50/53.x compatibility notes on any entry. Verified, primary source, and arguably the single strongest piece of evidence in this whole follow-up: it is not just that individual packs lack ports, the community's own indexing effort hasn't reached this content area either.
- **DFFD's tileset category, sorted by most recently updated, confirms nothing new.** The only post-v50 (2023–2026) entry resembling a graphics update at all is *"Curses of Balin 10x12, 10x16 'n 16x16 1bit"* (Aug 2026) — its own filename ("1bit") marks it as the same font-only variant the first pass already found and correctly separated from Balin's actual sprite pack (which remains 0.47.05-only). No new sprite-pack candidate surfaced. Verified, primary source (absence-of-evidence, checked directly rather than assumed).

### Same-style alternatives: none found

Targeted WebSearches for "detailed sprite tileset v50," "Darkest Dungeon style sprite v50," "moody detailed sprite tileset free download," and community-recommendation queries aimed at Reddit/r-dwarffortress-style discussion all returned the same small, already-known set of names (Vettlingr, Obsidian, Curses of Balin, Meph) with no v50-confirmed newcomer and no discussion thread (Reddit or otherwise) describing a genuine port.
