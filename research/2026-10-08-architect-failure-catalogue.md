# Architect failure catalogue (2026-10-08)

Scope: every real problem this project has hit in building, digging, siting, room design, access, doors, stairs, blueprints/quickfort, reservations and construction. Compiled for an Opus designer cross-checking a failure-mode analysis.

## How this was built, and its limits (read first)

- Mined by seven parallel Sonnet read-only passes over: `decisions/DECISIONS.md` (all rows), `docs/TRAPS.md`, `Working.md`, `agents/architect/role.md`, `scripts/dfhack/TOOLS.yaml` notes, `evals/live/*/README.md`, `handoffs/*.md` Results, `working-archive/*.md`, `research/*.md`, and "found live" header comments in `scripts/dfhack/*.lua`.
- **The same incident appears in several sources** (register row, TRAPS entry, eval README, handoff). The ledger (Part 4) is per source mention: **370 raw entries, not 370 distinct incidents**. Part 1 is the deduplicated view (about 60 distinct incidents, hand-merged by me); the ledger is the evidence trail. I did not hand-merge all 370, so a few distinct incidents may be missing from Part 1; the ledger is the superset.
- **Coverage gaps, honestly:** the TRAPS/TOOLS pass read TOOLS.yaml by grep and line ranges, not in full. The handoffs/archives pass sampled most Results by keyword; it skipped the 2026-08-24 archive, infra parts of 2026-09-07, planner P1a/P1b and rooms cutover stages 2a-2e. The evals pass read only the top of the wiki-mirror README. Four consultant-* eval dirs have no README (answer.md read instead). Some entries are marginal (embark UI, harness bugs) and are kept because they touch tool trust.
- **Guard status is as the sources state it.** I did not re-read code or run tests in this pass. "Code-enforced" means a source says a code path enforces it; "none" means no source says a guard exists. Confirm before relying on either. Inferences are marked [inferred]; miners' own marks are carried through.
- One primary class per incident, though many are cross-class.

### 3b. Recurring patterns (my synthesis; each is supported by several ledger entries)

1. **Silent success on a no-op.** Designations, blueprints, quickfort sections, finders and orders return success or empty while doing nothing (grass downstair, hidden-rock dig, `#meta` swallow, off-map z returning [], orders `validated:true`). Detected by waiting and observing, rarely by the tool. The fix pattern that worked: make the tool refuse or report a state (`would_strand`, `isError`, stall states).
2. **A check that proves an adjacent property.** Entrance reachable but not on circulation; walkable tile beside footprint but not reachable from the fort; "was mined" inferred from "is open"; coarse stockpile category; stuck job vs finished job.
3. **Order of operations is data the tools do not model.** Stair before dig beneath, zone after furniture, smooth after mine, hallway before rooms, shell before wall ring, item supply before build. Guards exist per case; none is a general dependency check.
4. **Perception false negatives drive agent misdiagnosis.** Ramp-top reachability, room-value proxy, 0-of-26,784 flood flags, a paused fort looking broken: the agent concludes failure or absence. Several were found only because the user or orchestrator checked live.
5. **Offline tests cannot see the game.** Fake worlds lack reachability, 1-indexed fakes of 0-indexed vectors, canned wire payloads; defect classes survive green suites. The guard is a live negative control, process only.
6. **Folklore and recall become rules.** Door/enclosure/room-value beliefs, `world.flows`, the water-source zone "fix". Guard is doctrine entries marked refuted or non-rule, text only.
7. **Siting is a static heuristic.** One sort, haul distance for everything, level-only search; office outdoors, coffin, water zones, farm/still collisions all route to the owed districting/circulation design.
8. **Single scarce resource stalls everything.** One pick, a reservation that does not pin, one allowlist gap.
9. **Self-inflicted action on stale state.** Hand-unsuspending a job, wedging the pipe with an unbounded query, proposals acting on stale reads.
10. **Detection by the user remains common** for geometry and circulation problems (bedroom block, water zones, first diagnosis of the border-less dig); code detection mostly arrives after a live run.
