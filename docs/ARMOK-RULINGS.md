# Armok rulings

The user's rulings on individual DFHack tools tagged `armok`, in the order they
were made. The rule itself is in `CLAUDE.md` ("No armok capabilities"): banned
are powers a player does not have (heal, teleport, spawn, skip costs, alter the
world) and information the game hides; reading what a player can already see
is fine however it is implemented. The tag is only a pointer.

The evidence for each tool is in `research/2026-09-21-armok-review.md`
(documentation read only, nothing run). **A ruling here is the user's decision;
the review is advice.** A tool not listed here has no ruling yet, and the
default for an armok-tagged tool is to check it against the rule before use.

| Tool | Ruling | Date | Reason and conditions |
|---|---|---|---|
| `caravan list` | **allowed, restricted output** | 2026-09-21 | Read in `caravan.lua`: prints id, race and civ, trade state, days remaining (an internal countdown), and four flags (casualty, hardship, goods seized, offended). Vanilla (wiki Trade page, current) does not show a countdown; it only mentions a "leaving soon" announcement. Ruling (user agreed, 2026-09-21): a wrapper returns only the id, race and civ, and the trade state (approaching, at depot, leaving); **days remaining and the four flags are withheld** until confirmed player-visible. |
| `caravan extend` | **banned** | 2026-09-21 | A power: keeps merchants longer than the game allows. Useful, and the case the project actually hit, but it gives something the game does not. |
| `caravan happy` | **banned** | 2026-09-21 | A power: makes merchants happier. |
| `caravan leave` | **banned** | 2026-09-21 | A power: makes merchants go away. |
| `caravan unload` | **open, deferred** | 2026-09-21 | Repairs a bug where a caravan's goods do not unload. The user left it open: there is no reason to use it yet, so it can wait until a caravan actually gets stuck. |
| `showmood` | **allowed only through a restricting wrapper** | 2026-09-21 | The DFHack command has no options and no readable source on this install, but a wrapper of ours can restrict what an agent receives. Per two ChatGPT answers citing the wiki (unverified by us): vanilla v50 shows material categories through the claimed workshop's clues, exact secondary quantities (each clue shows two seconds per item) and the items already collected; the primary material's clue shows once whatever the quantity, and the quantity is random (1 to 3 base items), so `showmood` gives an information advantage only in the exact primary quantity before it can be observed, and in requirements before a workshop is claimed. **Ruling (user agreed, 2026-09-21):** agents never get the raw command; a wrapper returns only the claimed workshop's categories in clue order, secondary quantities, items already collected, and the primary quantity as the range 1 to 3, not the exact figure. A moody dwarf's primary need is then met the way a player would meet it, by supplying the maximum. |
| `lever list`, `show`, `pull` | **allowed** | 2026-09-21 | `list` aggregates what a player sees by selecting each lever (name, state, links); `pull` queues a normal job that a dwarf performs. |
| `lever pull --priority` | **allowed** | 2026-09-21 | Sets the job's `do_now` flag (read in `lever.lua`), which matches the vanilla priority button (a ChatGPT answer citing the wiki; the button-to-flag mapping is unconfirmed). Real use: emergency drawbridges and traps. |
| `lever pull --instant` | **banned** | 2026-09-21 | Pulls the lever directly with no dwarf doing a job: a power. |
| `locate-ore` (default mode) | **allowed in principle; not expected to be used** | 2026-09-21 | Read in `locate-ore.lua`: without `--all` it requires `dfhack.maps.isTileVisible` and the vein's own `discovered` flag, stricter than `prospect`. Its extra action is an ordinary dig designation plus a camera move. The script looks buggy (`row & (1 << x) == 1` is only true for the first column of a block; unrun) and prints no coordinates, so our own wrapper would read the same flags itself, and `prospect` plus our dig tools may make it unnecessary. |
| `locate-ore --all` | **banned** | 2026-09-21 | Skips both visibility gates and includes undiscovered veins: hidden information. |
| `prospect` | **allowed (default mode only)** | 2026-09-21 | Verified by reading `prospector.cpp` at the 53.16-r1 tag and the install's own `hack/lua/plugins/prospector.lua`. `all` sets the plugin's `hidden` option and `hell` sets it plus `tube`; the default sets neither. In the default mode the tile loop skips every hidden tile (`if (!options.hidden && des.bits.hidden) continue`) **before** it counts aquifer, lair, liquids, base materials, layers or veins, so **all nine report sections** are built from non-hidden tiles only. HFS tubes are counted only for hidden tiles, which are skipped unless `all` or `hell` is given, so default mode never reports them. Shrubs and trees use the same hidden test. **Ruling (user agreed, 2026-09-21):** default `prospect`, every section, allowed; `all` and `hell` banned. The `features` section can print `Has lair` (an occupancy flag on a revealed tile) and I could not confirm vanilla displays a lair flag, so **a wrapper drops that one line** (my reading of "agreed"; reversible). |
| `diplomacy` (no arguments) | **allowed, `Mutual` column dropped** | 2026-09-21 | Read in `diplomacy.lua`: the list walks the player civ's own relation entries and prints id, Peace or War, name, and a `Mutual` column read from the other civ's own stance. Vanilla (wiki "Civilization" page, current text; the "Diplomacy" page is a migrated 2014 article and did not answer): the `c` then `c` screen shows only civilizations the player has contacted, with `P` or `W` shown for how listed civilizations relate to each other. A read-only run on the paused fort listed 5 civilizations while the world has 16, consistent with contact-only but not proof it matches the vanilla list. Proposed: the list allowed with `Mutual` dropped (the other side's own stance is not shown as a separate value in the vanilla text). |
| `diplomacy all <REL>`, `diplomacy <CIV_ID> <REL>` | **banned** | 2026-09-21 | Sets peace or war with any civilization on both sides at once (the script writes both civs' relation fields): a power. |
| `justice list` | **allowed** | 2026-09-21 | Reads `plotinfo.punishments` and prints each convict serving a sentence with the days remaining. Vanilla (wiki Justice page for v53.16): the `j` screen's Convicts tab shows each convict's pending sentences and crimes; the page does not say remaining versus total, a minor gap since a player can work out the remainder. |
| `justice pardon` | **banned** | 2026-09-21 | Sets the sentence counter to zero: a power. |
| `assign-preferences --show`, `pref-adjust list`, `pref-adjust show` | **allowed in principle; not expected to be used** | 2026-09-21 | Read-only forms only. Vanilla (wiki Preferences page, current): a citizen's preferences are shown under Personality/Preferences; the page does not say any are hidden. Neither script would be wrapped: preferences are a unit field read directly by id in the dwarf-assessment tool, and `pref-adjust list` prints only static token lists. |
| `assign-preferences` with `--reset`, `--like*`, `--hate*`; `pref-adjust all`, `one`, `goth`, `clear` and variants | **banned** | 2026-09-21 | Rewrite or clear a dwarf's preferences: a power. |
| `clean` (all forms), `spotclean`, `clear-smoke` | **banned for now, open for FPS** | 2026-09-21 | The user: ban for now but leave it open for FPS. Findings: vanilla can remove spatter (wiki Contaminant page, v53.16: a dwarf cleaning task, building on the tile, smoothing a wall, water or mist) and does not say spatter fades on its own; DFHack's doc says cleaning can significantly reduce FPS lag in an old fortress. Vanilla smoke dissipates about 7 seconds after its source is gone (wiki Smoke page, v53.16), and inhaling it gives unhappy thoughts. `clean items` strips weapon poisons and `clean units` includes hostiles, so those have gameplay effects. **Revisit only if FPS drops:** the candidate then is `clean map` with no mud or snow options, run by the harness on a schedule (never by an agent) and logged. |
| `geld` (all forms, including `--ungeld` and `--toggle`) | **banned for now, optional later** | 2026-09-21 | Read in `geld.lua`: writes the gelded flag, a fabricated wound and the body-part status directly, with no job, labor or workshop, and `--ungeld` reverses it. Vanilla (wiki Gelding page, v53.16): a designation from the `u` screen's Pets/Livestock tab, performed as a job by a dwarf with the Gelding labor at a farmer's workshop; the page does not say whether it can be undone. The vanilla designation covers the real need (stopping breeding). **Later option:** our own tool sets the vanilla mark for gelding (the field is probably `unit.flags3.marked_for_gelding`, unverified) and a dwarf does the job. |
| `cursecheck` (all forms) | **banned** | 2026-09-21 | Read in `cursecheck.cpp` at 53.16-r1: loops over every loaded unit (`world->units.all`) with no visibility check and classifies each as ghost, zombie, necromancer, werebeast or vampire from internal fields. DFHack's own doc notes some vampires use fake identities in-game. It reveals what the game deliberately hides, and `nick` also writes a nickname. Banned however implemented. |
| `lair` (all forms) | **banned for now, open** | 2026-09-21 | Read in `lair.cpp` (56 lines): sets the `monster_lair` occupancy flag on every tile of every map block, which stops item scatter when a site is abandoned and reclaimed. `docs/PURPOSE.md` treats forts as mortal and reclaims after a death, and scatter is a vanilla consequence, so this removes a cost and softens the format. **Not a mild ban:** it removes the cost of a fort's death, which the project treats as its format (the review called it the softest on its list; the user doubted that and it is not established). It is open only because reclaim is unproven and buggy, not because the power is small. **Revisit only if** reclaiming after a death costs more than the format intends. The same flag is what `prospect`'s "Has lair" line reads, which is why a wrapper drops that line. |
