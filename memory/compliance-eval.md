# Compliance eval

The doctrine-compliance eval harness: build, the DeepSeek provider, and the full 180-cell sweeps against both providers (including the Opus cost overrun). Long register rows moved here 2026-09-15.

### 2026-09-11: Second compliance-eval provider added (DeepSeek); first 180-cell sweep

**Decision:** **Added a second provider to the compliance eval harness (DeepSeek, via a generic OpenAI-compatible adapter), and ran the first full 180-cell sweep against it** — not a speculative feature: the user's own stated direction is multiple concurrent sessions/roles via `openclaw`, with model choice made per role, so "where does compliance collapse" only means something once asked of whichever model actually runs a given role

**Status:** accepted, built, real finding

**Reason:** `evals/compliance/harness/providers.py` now separates the request/response shape (`call_anthropic` vs `call_openai_compatible`) from everything downstream (grading, JSONL rows, `report.py`), so a new provider is one adapter function plus an env-var/base-url entry, not a rewrite. `report.py` now splits its output by model when a file mixes providers. **The `deepseek-chat` full sweep (10/20/40/80/120/160 rules x 3 formats x 10 scenarios, 180 cells) is a real, if single-run, finding**: perfect-response rate is 70-83% at n=10/20, then **collapses to 0% from n=40 onward** — far earlier than "Prompt Design at Scale"'s own ~80-rule collapse point for the models it tested, confirming this project's own instinct not to reuse that paper's number blind. Per-rule pass rate tells a different, more useful story: it degrades gently (97% → 72% from n=10 to n=160), and the category breakdown shows the collapse is concentrated almost entirely in `required_word` (20.6% pass rate at n=160) while `banned_word` stays at 100% (2399/2400) — this model is far more reliable at *not* doing something across many simultaneous rules than at reliably inserting many specific required words, a real and actionable asymmetry for how DF doctrine should be phrased. Full data: `evals/compliance/results/deepseek-full-2026-09-11.jsonl`. **The `claude-opus-5` sweep was still in flight at session's end** (same 180-cell matrix) — mid-run, the user raised Opus's cost for a run this size as a live concern; asked directly rather than assumed, and the user's call was to let it finish rather than stop partway, while flagging that this harness's default model choice is a real open design question once `openclaw`'s per-role model selection exists, not resolved here. → `Working.md`, `evals/compliance/README.md`.

### 2026-09-11: Compliance eval harness built

**Decision:** **Built the compliance eval harness** (`evals/compliance/`), research build-order item 1 (`research/2026-08-25-learning-architecture.md` §7) — chosen as the session's task specifically because it needed neither VM 103 nor the `perception-layer-experiments` branch/worktree, both held by a concurrent peer session at the time

**Status:** accepted, built, selftested, and live-smoke-tested

**Reason:** Mirrors `evals/perception/`'s structure and philosophy exactly: a synthetic doctrine pool (~170 independently verifiable rules — banned/required words, banned punctuation, word-count bounds, an exact prefix/suffix/sentence-count/lowercase/no-contractions/no-digits/no-first-person/ends-with-`?`), nested so `rule_set(n)` is always a strict subset of `rule_set(2n)`, rendered in three formats (markdown/plain/prose), and graded purely mechanically against raw response text — no LLM ever judges another model's compliance, matching this register's 2026-08-25 standing position. `selftest.py` caught two real bugs before any live call: a synthetic test string that accidentally contained the very word its own rule banned, and a `max_word_count` floor (60) tighter than the 60 mandatory `required_word` rules plus prefix/suffix overhead could jointly fit under at high doctrine sizes — the pool was not actually satisfiable at its own maximum N until the floor was raised to 80, caught by a selftest that constructs one candidate response and checks it against every rule in the largest configured set, not by inspection. A live smoke test (4 cells, `claude-opus-5`, `.env`'s `ANTHROPIC_API_KEY` — initially missed, since an earlier shell check of the bare env var had produced a false positive from a quoting bug) ran for real end to end: 100% perfect compliance at 10 rules, dropping to 50% perfect (98.8% per-rule; the one miss was `max_word_count`) at 40. Too small a sample (n=2/cell) to be a finding, but confirms the request/grading path works against the live API, not just a stub. **Not yet run at the paper's full rule-count sweep (10/20/40/80/120/160) or at meaningful sample size** — that real run is the next concrete step, not done this session. → `evals/compliance/README.md`.

### 2026-09-11: Full 180-cell sweep both providers; Opus cost overrun, DeepSeek made default

**Decision:** **Ran the compliance eval's full 180-cell sweep against both providers; the `claude-opus-5` run cost $9-13 in real API spend, which the user flagged mid-run and, once a real harness bug compounded it, told this session directly to stop — DeepSeek is now the harness's default provider**

**Status:** accepted, **cost overrun, corrected**

**Reason:** `deepseek-chat`'s full sweep is clean, complete data and the one to trust: perfect-response rate 70-83% at n=10/20 collapsing to 0% at every n≥40 (earlier than "Prompt Design at Scale"'s own ~80-rule collapse for the models it tested), with per-rule pass rate degrading gently (97%→72%, n=10→160) and the collapse concentrated almost entirely in `required_word` (20.6% pass rate at n=160 vs. `banned_word`'s 100%) — a real, actionable asymmetry: this model is far more reliable at sustained *avoidance* than sustained *inclusion* across many simultaneous rules. **A real harness bug was found mid-run, not after**: `claude-opus-5`'s original sweep used `max_tokens=4000`, and adaptive thinking at n=120/160 sometimes consumed the entire budget before any text was emitted — confirmed by reproducing it directly (a single n=160 call spent 3469 of 4000 tokens on thinking alone) — so 27 of 180 cells (77% of n=160) came back with **zero text**, a token-budget artifact, not a compliance finding; `max_tokens` is now `16000` by default and the empty-response error path now captures token counts for diagnosis, so this class of failure is visible in future data rather than silently dropping `n_runs`. **The user was asked directly, mid－run, whether to stop the Opus sweep given cost** (the two priciest batches, n=120/160, were still ahead) — chose to let it finish and flagged model-cost-per-eval-run as a live design question, not resolved at that point. After the full sweep landed (~$9 by then) plus a rerun of the fixed n=120/160 cells (46/60 cells before being stopped), the user's follow-up call was sharper: **stop spending on Opus, default the harness to DeepSeek going forward, and document what exists** — `run.py --provider` now defaults to `deepseek` (`anthropic` remains fully supported, opt-in only). Total session spend, computed from recorded `input_tokens`/`output_tokens`/`cache_read_tokens` against Anthropic's published per-token rates: **~$9-13 for claude-opus-5** (~250 calls, overwhelmingly `thinking`-token output at $25/MTok), **~$0.05-0.10 for deepseek-chat** (184 calls) — a roughly 100x cost gap for comparable eval coverage, itself now cited as evidence for `openclaw`'s eventual per-role model selection rather than one global default. Opus's own perfect-response curve is noisy and non-monotonic across doctrine sizes at `--repeats 1` (30 runs/size split three ways by format) and should not be read as a clean collapse point without more samples — flagged honestly rather than papered over. Full data: `evals/compliance/results/{deepseek-full,full,full-fix}-2026-09-11.jsonl`. → `evals/compliance/README.md`, `Working.md`.
